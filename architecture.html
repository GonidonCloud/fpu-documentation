FPU Architecture

How a Flow Processing Unit turns a pipeline description into continuously flowing data.

Chip topology

An FPU chip is a two-dimensional mesh of flow cores. Each core is an independent dataflow engine with its own stage array, flow queues, and fabric router. Cores never share a program counter — there is nothing to share. The host system sees the FPU through a standard PCIe Gen5 endpoint or a native FlowFabric port, depending on the enclosure.

Flow cores and stages

Each flow core contains up to 256 reconfigurable stages. A stage is the smallest unit of execution: a pipelined functional block that consumes tokens from an input flow queue, applies a kernel, and emits tokens to one or more output queues. Stages are grouped into lanes; a lane processes one token stream in strict order, while lanes within a core run concurrently.

Every stage has three binding parameters, fixed when the pipeline is placed:

ParameterDescription
KERNEL_IDIndex into the core's kernel ROM / reconfigurable kernel memory.
QDEPTHDepth of the stage's input queue (2–512 tokens).
UPSTREAM[]List of fabric channels feeding this stage.

FlowFabric interconnect

FlowFabric is the on-chip network that carries tokens between stages, cores, and I/O ports. It is a credit-based, lossless network with deterministic routing: once a pipeline is placed, the path of every flow is known at compile time, which is what makes end-to-end latency on an FPU predictable to the nanosecond.

  • Per-hop latency: 18 ns (v2), including flow-control overhead.
  • Bisection bandwidth: 3.2 Tbps on-chip (v2 die).
  • External links: 4 × 400 Gbps FlowLink ports per device.

Flow memory hierarchy

Unlike a cache-based processor, the FPU exposes managed memory explicitly:

LevelSize (v2)LatencyScope
Stage registers64 KB / stage1 cycleSingle stage
Flow memory tile4 MB / tile~9 cyclesNeighboring cores
Core scratchpad32 MB / core~35 cyclesOne flow core
Device HBM32 GB~180 cyclesAll cores

Flow memory tiles are the key to sustained throughput: state that would cause a cache thrash on a CPU (routing tables, stream windows, feature stores) is pinned into a tile and addressed by the stages that own it. There is no coherence protocol to pay for, because ownership is static.

info
Note
Because ownership is static, the compiler rejects any pipeline where two stages write to the same flow memory region. Use a reduce stage to merge streams instead.

Backpressure and flow control

The FPU is a push-based device: an upstream stage may only emit a token when it holds a credit for the downstream queue. If a slow stage builds up, backpressure propagates backward through the fabric to the source — the device never drops or overwrites in-flight data. Correct pipelines therefore need to bound their state: a stage that buffers an unbounded window will eventually stall its lane. 

// A pipeline that cannot deadlock: window size is bounded.
flow pkt_in  --> window(4096) --> classify --> sink(out_stream);

Security model

Pipelines are isolated at placement time. Each loaded pipeline gets a flow namespace: a set of fabric channels, memory regions, and I/O ports it may touch. The fabric router drops — and logs — any token that leaves its namespace. Bitstreams are signed with GonidonCloud device keys, and the host driver verifies signatures before placement.
