Programs and device arrays

FlowKit separates a computation's definition from its execution. Python functions built from fk operations describe a tensor graph. Compiling that graph returns a callable program with fixed argument contracts. Device arrays represent typed storage on an FPU and can pass between compiled programs without a host copy.

  • Host NumPy arrays are copied explicitly with fk.to_device.
  • Device arrays are immutable from the program author's perspective; an operation returns a new logical value.
  • Launches are asynchronous. Retrieval or block_until_ready() establishes a synchronization point.
  • A compiled program can be saved as a .flb file and loaded by another process using the same target.

Graph compilation

This example compiles a linear layer followed by a bias addition and ReLU:

import flowkit as fk

def linear_relu(x, weights, bias):
    hidden = fk.matmul(x, weights)
    return fk.relu(hidden + bias)

program = fk.compile(
    linear_relu,
    x=fk.TensorSpec((64, 768), "bfloat16"),
    weights=fk.TensorSpec((768, 3072), "bfloat16"),
    bias=fk.TensorSpec((3072,), "bfloat16"),
)

x = fk.to_device(input_batch, dtype="bfloat16")
weights = fk.to_device(model_weights, dtype="bfloat16")
bias = fk.to_device(model_bias, dtype="bfloat16")
output = program(x, weights, bias)

The compiler can fuse the bias addition and activation with the matrix operation's output path, avoiding a round trip to HBM for each intermediate. Fusion decisions depend on target, shape, and data type; do not encode application behavior around a particular fusion choice.

Inspecting the compiled artifact

print(program.signature)
print(program.resource_report)

program.save("linear_relu.flb")

The resource report lists HBM and SRAM high-water marks, assigned clusters, collective operations, and any unsupported operations left for the host. The standalone flowc explain linear_relu.flb command prints the same information without loading the runtime.

Shapes and layouts

A TensorSpec defines rank, dimension sizes, and storage type. Static shapes give the compiler the most scheduling freedom. For variable input sizes, compile a bounded set of shape buckets and pad each input to the nearest bucket. 

programs = {}
for batch in (1, 8, 32, 64):
    programs[batch] = fk.compile(
        linear_relu,
        x=fk.TensorSpec((batch, 768), "bfloat16"),
        weights=fk.TensorSpec((768, 3072), "bfloat16"),
        bias=fk.TensorSpec((3072,), "bfloat16"),
    )

# Application code selects a bucket and tracks the valid input rows.
executable = programs[8]
result = executable(padded_x, weights, bias)

Padding should not change the requested result. Mask padded rows before reductions such as mean or softmax when they would otherwise contribute to the output.

Logical shape versus physical layout

Program code uses logical row-major tensor shapes. The compiler may store tiles in a different physical order to match the matrix array. Layout annotations in a Flow binary describe this representation; explicit layout choices are needed only for custom operators or foreign-memory interfaces.

Precision control

FlowKit preserves the dtypes in the captured graph unless compilation options request a conversion. Use explicit casts at model boundaries and choose accumulation behavior for matrix operations independently of storage type. 

options = fk.CompileOptions(
    matmul_dtype="bfloat16",
    accumulator_dtype="float32",
    allow_precision_change=["matmul"],
)

program = fk.compile(
    linear_relu,
    options=options,
    x=fk.TensorSpec((64, 768), "float32"),
    weights=fk.TensorSpec((768, 3072), "float32"),
    bias=fk.TensorSpec((3072,), "float32"),
)

Narrow matrix inputs can improve throughput and reduce memory traffic, but outputs will not be bit-identical to a float32 reference. Validate task-specific accuracy across a representative dataset. For quantized models, retain calibration scales in the FlowModel package so they survive compilation and deployment.

Multi-device programs

A mesh names a logical set of devices. Sharding rules map tensor dimensions to mesh axes, while collective operations define how partial results are combined. The compiler uses both to produce per-device command streams. 

mesh = fk.Mesh(devices=[0, 1, 2, 3], axis="data")

# Split the batch dimension; every device keeps a full weight copy.
x_sharded = fk.shard(x, axis=0, mesh=mesh)

# Sum partial gradients and return the result on every participating device.
gradients = fk.collectives.all_sum(local_gradients, mesh=mesh)

Choosing a parallel strategy

StrategyWhat is partitionedMain communication
Data parallelExamples in a batchGradient sum or mean
Tensor parallelMatrix rows or columnsActivation gather or reduction
Pipeline parallelContiguous model stagesPoint-to-point activation transfer

Strategies can be combined on different mesh axes. Start with data parallelism for models that fit on one device; introduce tensor or pipeline partitioning when capacity or matrix efficiency requires it.

Importing a model

A FlowModel package (.flm) contains a portable graph, weights, tensor metadata, and optional quantization parameters. Import a supported ONNX graph, inspect operator coverage, and then compile the package for each target: 

flowc import model.onnx --output model.flm
flowc operators model.flm --unsupported
flowc compile model.flm --target fpu-m2 --output model.flb

Deploy the resulting binary through the same runtime API as a Python-compiled program:

import flowkit as fk

classifier = fk.load("model.flb")
logits = classifier(fk.to_device(batch, dtype="bfloat16"))
logits.block_until_ready()

Unsupported operators must be replaced, implemented as an extension, or moved into a preprocessing or postprocessing stage on the host. An import succeeds only when the complete graph has an explicit execution plan.

Debugging

  • Run a small static-shape case with FLOW_TARGET=sim and compare against a host reference.
  • Set FLOW_SYNC=1 to surface a launch error at the calling operation during development.
  • Use fk.debug.print(value) inside a captured function to emit selected device values at synchronization points.
  • Set FLOW_CHECK_NUMERICS=1 to insert NaN and infinity checks around operation boundaries.
  • Disable optional fusion with fk.CompileOptions(fusion=False) only to isolate a suspected compiler issue; restore it for production benchmarks.
