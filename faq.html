COMMON QUESTIONS

FPU FAQ

Compatibility, programming, deployment, and troubleshooting in one place.

What does FPU stand for?

Flow Processing Unit. “Flow” describes the compiler-managed movement of tensor tiles between memory and compute resources. It does not mean floating-point unit, although FPUs support floating-point tensor formats.

Is an FPU a GPU?

No. Both can accelerate parallel numerical work, but an FPU is designed around compiled tensor graphs, explicitly scheduled on-chip memory, and multi-device collectives. A system can include both: for example, a GPU can render or preprocess media while an FPU executes a trained model.

Which model formats and frameworks are supported?

FlowKit programs can be written directly in Python. The standalone compiler also imports supported ONNX operators into the portable FlowModel format. Framework exporters produce .flm packages without changing the runtime API. Run flowc operators model.flm --unsupported to check a particular model before compiling it.

Can FPUs train models as well as serve them?

Yes. E1 is intended primarily for inference, while M2 and M4 support training and inference. FlowKit provides differentiation for captured graphs, and multi-device meshes support gradient collectives. Memory capacity must include parameters, gradients, activations, and optimizer state—not just model weights.

How do variable batch sizes and sequence lengths work?

Compile a bounded collection of static-shape executables, pad inputs to the nearest supported shape, and mask padded values where they could affect a result. This makes memory use predictable and avoids compilation in a serving loop. See Shapes and layouts for an example.

Will bfloat16 or int8 change model accuracy?

It can. Lower-precision storage changes rounding and, for integer formats, introduces quantization error. FPU matrix operations can accumulate bfloat16 inputs in float32, but that does not make the result identical to a full float32 graph. Evaluate the final task metric using representative data and production quantization parameters.

Why does a model fit in HBM but fail to compile?

HBM capacity is only one constraint. A tile schedule must also fit cluster SRAM, engine registers, command buffers, and communication resources. Inspect program.resource_report or the compiler diagnostics to identify the exhausted level. Changing tile size, activation lifetime, or partitioning can help even when total HBM use remains similar.

Can several applications share one FPU?

Yes, when the device policy enables multiple runtime contexts. Each context receives isolated queues and memory allocations. Compute is time-sliced or assigned reserved clusters according to that policy. Sharing does not guarantee unchanged latency, so validate co-located workloads under realistic load.

Is the simulator useful for performance testing?

No. fpu-sim is a functional target for checking shapes, numerical behavior, and application integration on a CPU. It does not model device timing. Use physical hardware and synchronized benchmarks for all capacity and latency decisions.

Are FPU results deterministic?

A fixed binary, input, target, and deterministic compilation mode produce repeatable operation ordering. Multi-device reductions and atomics can introduce ordering differences unless deterministic collectives are enabled. Floating-point results can also differ across targets or compiler versions because tiling and fusion affect rounding.

Can a Flow binary run on every FPU model?

No. A .flb file is target-specific. Keep the original Python program or .flm package as the portable artifact and compile it for every deployment target. The runtime checks the target and tensor signature before launch.

How do I locate a failing operation?

Start with FLOW_SYNC=1 so errors are reported near the launching call. For numerical failures, enable FLOW_CHECK_NUMERICS=1 and reproduce with a small input on the simulator. These options add synchronization or checks and should not remain enabled for production performance measurements.
