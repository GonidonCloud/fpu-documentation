A different FPU
In this documentation, FPU means Flow Processing Unit, not floating-point unit. The name refers to the movement of tensor tiles through a compiled execution graph.

What an FPU does

A Flow Processing Unit is a domain-specific accelerator for machine learning and other dense numerical workloads. It executes operations on multidimensional arrays, called tensors, using parallel matrix and vector engines. A host CPU prepares input, launches compiled programs, and handles application logic; the FPU performs the compute-intensive portion of the job.

The Flow compiler lowers a model into device instructions, assigns intermediate values to memory, and splits large operations into tiles. This ahead-of-time plan reduces host dispatch work and lets the device overlap computation with data transfers. The same programming interface targets physical devices and the functional simulator.

Platform building blocks

01

Tile-based compute

Matrix engines process dense blocks while vector lanes handle normalization, activation, and elementwise operations.

02

Explicit memory movement

The compiler schedules transfers between host memory, device HBM, and cluster SRAM to keep operands close to compute.

03

Whole-graph execution

Programs are compiled once and invoked repeatedly, avoiding a host round trip for every operation in a model.

04

Workgroup collectives

FlowMesh links carry gradients and activations between devices for data, tensor, and pipeline parallel execution.

Where FPU fits in a system

FPU is an accelerator, not a host replacement. A typical service uses each class of processor for the work it handles best.

ComponentPrimary responsibilityExamples
Host CPUApplication and control logicRequest handling, preprocessing, data loading

From source to execution

  1. Describe the computation. Build a program with the FlowKit Python API or import a FlowModel package.
  2. Select a target. Compile for an installed FPU or the simulator; shapes and data types become part of the executable contract.
  3. Move inputs. Transfer tensors to device memory and invoke the compiled program.
  4. Consume outputs. Keep results on device for the next program or copy them back to the host.
import flowkit as fk

program = fk.load("classifier.flb")
result = program(fk.to_device(batch))
probabilities = fk.from_device(result)
